## API, admission and required bindings

`routine [isa source-plan layout]` returns `:linux.static.capability/result`, with
`code`, `start`, `bindings`, `externals` and `error`. Only `error=:ok` authorizes consuming
the result. Failure has no partial code or bindings. Invocation refusals name
missing planned handlers, malformed grant, allow-bitmap offset, layout/workspace
or the shared string context-ABI checks.

The caller must first obtain an admitted plan from the owning planner, with
sealed ISA-matched decision artifacts, narrowed grants and context ABI, and
derive the unchanged expected layout with `image-layout`. This API checks its
needed offsets and arithmetic; it does not attest a supplied document, reverify
the entire artifact/layout or make a caller-created plan authoritative.

The explicit ISA must match the admitted source plan, decision artifacts and
assembler target; the caller owns that complete binding. The former two-argument
candidate API is replaced. `start` now includes common argv/envp/private-context/
clock initialization and must run exactly once after the entry captures kernel
argc/argv and before guest code. It does not implement filesystem/scope startup.

The candidate returns `:typed-cap-call -> :ls.cap/typed-cap-call` and
`:finish -> :ls.cap/finish`. Its required external labels are:

- `:ls.cap/c1-cap`, `:ls.cap/c1-decide`, `:ls.cap/h-decide`: addresses of the
  admitted compiled owning decision exports, not arbitrary callback hooks.
- `:ls/bad`, `:ls/trap-cells`, `:ls/trap-bytes`: real non-returning trap paths.
- `:ls/trap-exit`: the owning write-to-stderr/exit path, with p1=message,
  p2=byte length and t5=configured exit code, used by the entropy refusal.
- `:ls.cap/no-handler`: the owning profile's named typed-cap-call slot refusal,
  including its message, configured exit code and trap mechanism.
- The three remaining filesystem/spawn handler bodies in the table below.
  The seven others are supplied by the [canonical I/O component](linux-static-io-port.md).
  No empty implementation, dummy success or legacy-host fallback is emitted.

Missing external labels must fail assembly. The full prelude must install only
admitted slot bindings and retain its refusal stubs. These source APIs do not
grant a capability or authorize changing the profile.

## Call and result path

The gate saves s0..s4 and LR, loads its admitted image data base into s0,
and records the four incoming values. It calls C1 `cap-admitted` over the
context's four sealed mask words and wire id, then C1 `decide` operations 1
(kind rule) and 0 (provider), then owning handler `decide` operation 0 (routing).
Failed grants/kind decisions trap; missing routing goes to the named slot
refusal. Before string decoding it also requires string kind 1. Matching
non-string kinds must not let the provider-0 entropy/spawn fallback interpret
an integer payload as a string handle. This is an explicit representation
refusal; malformed-input diagnostic precedence is not claimed unchanged.

Every decision call keeps the reference's five visible argument registers and
separate hidden gctx/private context. The private context is data+1072, with
its fuel word at data+1080 reset to 9007199254740991 before each call. Owning
compiled decisions must honor their native ABI and preserve s0..s4. They do
not spend guest fuel/cells. This is not an allocation-capable guest context.

The request handle is resolved within code/pool windows and fully validated
as UTF-8 before any handler dispatch. The common finish path requires each
handler to store its result handle at data+1184 and branch to `:ls.cap/finish`;
it resolves and validates that result again before restoring state and returning.

ids 1..10. The current static limits blob
`9549aaf1fd92f975d8f58b1b7c80e8df95cfd153` likewise omits wire 3. This patch
does not pretend they enable hash or bypass the decision with an inline
provider-to-handler policy.

## Hash and pool ownership

When wire 3 is in the narrowed grant, the planner appends an aligned
816-byte `:hash-workspace` after its existing scratch regions. The gate checks
its non-wrapping span inside image memory and beyond the string pool. The
owning layout/verifier must additionally establish all actual mapped regions,
their disjointness and immutable request spans. Calls sharing one image context
must remain serialized, as with the existing per-context C3 scratch protocol.

The handler calls the private native SHA routine over the validated request
pointer/length. Its return must equal the workspace's 64-byte hex-result span;
zero or any other address traps. The pointer stays inside the mechanism.
The handler then asks the real owning `decide` op 6 for the 64-byte pool charge,
copies through the shared intern fragment, advances pool-used and performs
checked pair/cell allocation with an initially unvalidated handle. The common
finish path validates that handle. No pointer or identity answer is returned
as the digest. Code/pool/profile limits bound the admitted input; complete
resource and refusal behavior still needs native qualification. No new per-round
fuel policy is invented here.

## Remaining integration

Owning handler routing, the static profile's wire-3 entry, the three remaining
handler bodies, sealed decision text/export placement, complete prelude/context/
trap messages and ELF construction, native verification/Definition CIDs and
reviewed pins remain unfinished. The current static profile still has no
wire-3 provider. Enable it only with the complete native binding and evidence;
keep the actual artifact seal check and never substitute a host hash or an
always-valid verifier. Whole compiler self-rebuild remains open under JUN-200/202.

This change does not merge a PR, retire the C loader, qualify native CDCI,
weaken protection, stop a service or change a production route.
